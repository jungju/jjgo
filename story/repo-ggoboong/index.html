ggoboong: GitHub 이슈 옆에 붙여 둔 작은 꼬붕

ggoboong은 GitHub 이슈를 읽고, 필요한 댓글을 남기고, 반복되는 확인을 조금 덜어주는 작은 Go CLI다.

본문

ggoboong은 GitHub 이슈 옆에 붙여 둔 작은 꼬붕 같은 CLI다.

처음부터 거창한 에이전트를 만들고 싶었던 건 아니었다. 이슈를 읽고, 댓글을 확인하고, 같은 말을 또 쓰지 않게 조심하고, 필요하면 정리된 답변을 남기는 정도. 그 정도만 해줘도 하루에 여러 번 반복하던 작은 수고가 꽤 줄어들겠다고 생각했다.

자동화라고 부르기엔 아직 조심스럽다

ggo는 지금 단계에서 스스로 이슈를 감시하지 않는다. 서버도 없고, 웹훅도 없고, DB도 없다.

대신 사람이 CLI를 실행한다.

  • 특정 이슈를 읽는다
  • 댓글 목록을 가져온다
  • 이미 남긴 댓글이 있으면 멈춘다
  • 파일에 써둔 Markdown을 댓글로 남긴다
  • label로 이슈를 찾고 JSON으로 뽑는다

이 정도면 조금 심심해 보일 수 있다. 그런데 오히려 그 점이 마음에 들었다.

처음부터 “알아서 다 해주는 봇”으로 만들면 편해 보이지만, 실제로는 무섭다. 무엇을 보고, 언제 말하고, 어떤 조건에서 멈춰야 하는지 정하지 않은 자동화는 금방 부담스러워진다. 그래서 이 프로젝트는 한 발 뒤에서 시작했다.

사람이 버튼을 누르는 자동화

ggoboong의 중심에는 이런 감각이 있다.

내가 하긴 할 건데, 매번 손으로 반복하고 싶지는 않다.

예를 들어 이슈를 모아서 볼 때는 label을 태그처럼 쓴다. ggo:idea가 붙은 이슈를 찾고, 이미 ggo:close가 붙은 건 제외하고, 마지막 댓글이 ggoboong이 아닌 것만 골라볼 수 있다.

이건 완전한 자동 처리라기보다 작업대를 정리하는 일에 가깝다. 사람이 판단해야 할 부분은 남겨두고, 사람이 보기 좋은 모양으로 재료를 모아주는 것이다.

중복 댓글을 막는 작은 표식

가장 먼저 신경 쓴 건 중복이었다.

GitHub 이슈에 자동으로 댓글을 남기는 도구는 한 번 잘못 돌리면 금방 지저분해진다. 그래서 ggo run은 댓글 첫 줄에 <!-- ggo:v1 --> 같은 숨김 표식을 넣고, 이미 같은 표식이 있으면 새 댓글을 만들지 않는다.

별것 아닌 장치지만, 이런 작은 안전장치가 있어야 도구를 편하게 다시 실행할 수 있다. 실패했는지 모르겠어서 한 번 더 눌렀는데 같은 댓글이 또 생기는 상황은 생각보다 빨리 피곤해진다.

GitHub App으로 남기는 댓글

인증은 GitHub App installation token을 사용한다. 개인 토큰으로 모든 걸 퉁치기보다, 이 도구가 하는 일의 범위를 GitHub App 권한 안에 가둬두고 싶었다.

private key를 바이너리에 넣지 않고 로컬 설정으로 두는 것도 같은 이유다. CLI는 편해야 하지만, 편하다는 이유로 비밀값까지 같이 말아 넣고 싶지는 않았다.

ggo login은 설정 파일과 private key 위치를 준비해준다. 그 다음부터는 ggo issues, ggo comment, ggo run 같은 명령으로 필요한 작업을 이어간다.

실제로 남은 장면

스크린샷에서 마음에 드는 부분은 댓글이 “봇이 작성했습니다”보다 “옆에서 한 번 정리했습니다”처럼 보인다는 점이다.

아직은 사람이 먼저 이슈를 쓰고, 사람이 다시 확인하고, 그 사이에 ggoboong이 한 번 거들어주는 흐름이다. 그 정도 거리가 좋다.

AI를 붙인 도구를 만들 때 자꾸 자동으로 끝까지 보내고 싶은 마음이 생긴다. 하지만 어떤 일은 마지막 결정권을 사람이 쥐고 있는 편이 훨씬 안정적이다. ggoboong은 그 사이 어딘가에 놓인 작은 도구다.

Go로 만든 이유

이번에는 Go가 잘 맞았다.

설치가 단순하고, CLI로 빌드하기 쉽고, 한 번 컴파일해두면 실행이 빠르다. GitHub API를 호출하고, JSON을 뽑고, 설정 파일을 읽고, 테스트로 동작을 잡아두는 일도 담백하게 맞아떨어졌다.

큰 프레임워크가 필요한 프로젝트는 아니었다. 오히려 작은 실행 파일 하나가 내 작업 흐름 안에 조용히 들어오는 게 중요했다.

앞으로 붙이고 싶은 것

지금은 아직 단순하다. 하지만 이 단순함 위에 조금씩 더 올려볼 수 있을 것 같다.

  • 특정 label 조합의 이슈를 더 잘 모으기
  • 댓글 본문을 더 자연스럽게 템플릿화하기
  • 실행 결과를 사람이 검토하기 쉽게 보여주기
  • AI가 판단하기 전에 필요한 맥락을 정돈해서 넘기기

핵심은 “자동으로 다 해치우는 봇”이 아니다. 내가 하던 일을 내 방식대로 계속할 수 있게, 옆에서 반복을 덜어주는 작은 도구에 가깝다.
